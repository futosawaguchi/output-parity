# 同梱の題材

どの題材もこの作品のために作った架空のものです（TCPDF の例だけは、公開されている本物の OSS です）。実在の取引先・案件・金額は含みません。

| 題材 | つなぎ方・形式 | 旧 → 新 | 同梱の結果 |
|---|---|---|---|
| 見積書 | コマンド・PDF | PHP 7.4 → 8.5 | あり |
| 架空書店の注文管理 | Web アプリ・HTML と CSV | PHP 7.4 → 8.5 | あり |
| 作業日報 | コマンド・CSV（Shift_JIS） | Python 3.10 → 3.12 | あり |
| TCPDF の公式の例 65 本 | コマンド・PDF | PHP 7.4 → 8.5 | なし（composer で取得して動かす） |

## 見積書（`samples/estimate/`）

- 見積書を PDF で出す小さな PHP アプリ（`samples/estimate/app/estimate.php`）で、自分で書きました。PDF ライブラリは本物の公開 OSS です（TCPDF 6.2.26 / 6.3.0、FPDI 1.6.2）
- PHP 8.0 から、文字列と数の `==` の比べ方が変わりました。削除の印（`deleted`）が `""` や `"-"` の明細は、旧では `0` と等しいとみなされて表示されていましたが、新では表示されなくなります。合計欄は JSON の値をそのまま出すので、明細の和と合わなくなる見積書と、合ったままの見積書ができます（[README の「diff が同じでも結論が違う例」](../README.md#diff-が同じでも結論が違う例)）

## 架空書店の注文管理（`samples/bookshop/`）

- 書名・お客様・注文は作ったものです。PHP の内蔵サーバと SQLite で動きます
- PHP 8.1 から、SQLite から読んだ整数が、文字列ではなく数として返ります。そのため、ギフト包装の行が消えたり、在庫切れの本が「残りわずか」になったりします。画面は普通に出て、HTTP も 200 のままです
- 明細の無い注文は 0 で割り、PHP 8 では 500 になります
- 注文の書き出し（会計ソフト向けの CSV・Shift_JIS）では、クーポンの割引率が「10.0」から「10」になります

## 作業日報（`samples/worklog/`）

- Python 3.11 で、`datetime.fromisoformat` が受け付ける日付の形が広がりました。3.10 では読めずに飛ばされていた行が、3.12 では集計に入ります。落ちず、警告も出ず、合計だけが変わります

## TCPDF の公式の例 65 本（`samples/tcpdf-examples/`）

- TCPDF 6.3.0 に付属する公式の例を、書き換えずに動かします
- ローカル環境で測ると、64 本は差が無く、`example_050`（2次元バーコード PDF417）だけが PHP 8.5 で構文エラーになり、PDF が出ません
- この題材は結果を同梱していません。composer で取ってきて動かします（[全部動かす](setup.md)）

## ライセンス

TCPDF は LGPL-3.0 です。MIT のこのリポジトリに実体を入れないよう、`vendor/` は同梱せず composer で取得します。古いバージョンをわざと使うので、composer の脆弱性の勧告はパッケージ名で無視しています。
