# 仕組み

## 流れ

| 段 | すること | だれがやるか |
|---|---|---|
| 実行 | 旧の環境で1回、新の環境で2回、同じ入力から流す | プログラム |
| 変換 | 出力をテキストの行にする（PDF は pdf.js、HTML は見える文字とフォームの値、テキストはそのまま）。形式に依存するのはここだけ | プログラム |
| 毎回変わる値 | 新の2回で毎回変わる部分（日時・ID）を見つけて除く | プログラム |
| 比較 | 残った差を行で取る | プログラム |
| 判定 | 無害・要確認・壊れている と根拠。差なし・出力なし・読めないは、プログラムが先に決める | Claude |
| 検算 | Claude が書いた計算と引用を確かめる。合わなければ「無害」を「要確認」に上げる | プログラム |
| 原因 | ソースと入力データを読み、原因のファイルと行、直し方を示す（読むツールだけを渡す） | Claude |
| 確かめる | コピー（`work/`）に直し方を当て、全部の入力で流し直して差を見る | プログラム（人がボタンを押す） |
| 元に戻す | `work/` を元のソースから作り直す | プログラム |
| 元へ入れる | 元のソースにパッチを当て、もう一度実行して確かめる | 人 |

## Claude を使っていない所と、その理由

- 毎回変わる値は同じ環境で2回流して見つけます。落ちたもの・差が無いものは、終了コードと比較で決まります。確実に決まる所はプログラムで済ませ、判断の要る所だけを Claude に渡しています
- 直ったかどうかも、Claude ではなくプログラムが決めます。直し方を当てて全部の入力を流し直し、差が消えたかで決めます
- 判定のプロンプトに、照合のルール（「合計欄を探して明細の和と比べよ」など）は書いていません
  - そのルールが正しいかを確かめる基準が無いことが、そもそもの出発点です
  - ルールは帳票の種類ごとに要り、どれが要るかは壊れてみるまで分かりません

## 直したあと、元のソースへ

かわりめが書き換えるのはコピー（`work/`）だけで、元のソースは書き換えません。本番のコードを変えるのは人で、ふだんコードを変えるときと同じ流れ（ブランチを切ってコミットし、レビューを通すなど）を通るべきだからです。

「直りました」の下に、元のソースへ入れる3つの手順が出ます。

1. 元のソースの、そのファイルと行を開く
2. 画面の差分のとおりに直す。または「パッチを保存」して `git apply` で当てる
3. もう一度「実行して判定する」を押す。毎回、元のソースからコピーを作り直すので、直した元のコードで比べ直せます

- 直し方を続けて当てたときは、パッチに全部が当てた順に入ります
- 元のソースが変わっていて当たらないときは、パッチを作らず、理由を画面に出します
- 元のソースに直接当てるボタンは、わざと作っていません（押すだけで本番のコードが変わる形は、守りとして弱いため）

## 汎用性

- 形式に依存するのは「変換」の1か所だけです。比較・毎回変わる値の除外・判定・原因は、テキストの行しか見ません。形式を足すのは、`lib/compare/` にファイルを1つ足すことです（いまは PDF・テキスト・HTML）
- 言語にも依存しません。設定ファイルの `command` を変えるだけで、PHP の題材と Python の題材が同じツールで動きます
- システムへのつなぎ方も3つ（コマンド・ファイル・Web）で、設定ファイル1枚で切り替えます。ツールのコードは書き換えません
- 判定と原因探しのプロンプトに、見積書や PHP に固有の語は書いていません
