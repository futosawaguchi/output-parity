# 既存機能が壊れていないかの確認

大きく変えたあとは、テストが通っても画面や往復が壊れていることがある（関数が自分を呼び続ける事故は、テストを通り抜けて `npm run samples` で見つかった）。
下の順に**全部**確かめ、最後に表で報告する。壊れていたら直して `fix:` でコミットし、その項目からやり直す。

⚠️ 期待値は今のサンプル（入力 A〜D）のもの。サンプルや設定を変えたら、このファイルの期待値も同じコミットで直す。

## ⭐ まずスクリプトで（手で1つずつ動かさない）

⚠️ 手で全部やると30分かかり、開発が止まった。下の 1〜6 はスクリプトが確かめる。期待値は `scripts/check/expected.ts` と各スクリプトの中。

| コマンド | 中身 | 時間 | いつ |
|---|---|---|---|
| `npm run check` | 1（テスト・型・lint）＋ 2・2b（3 題材を Claude なしで流し、入力ごとに期待値と照合）＋ php のサーバの残り | 約1分 | コミットごと |
| `npm run check:screen` | 本番の形で組み立てて 3100 に立て、見えない Chrome で 4a・4i・4k・4l | 約1分 | 画面を変えたとき |
| `npm run check:all` | 上の全部 ＋ 3（Claude あり）＋ 4b〜4f（実行・原因・当てる・戻す・判定し直し）＋ 4h・4j（php が無いとき。設定は finally で戻す）＋ 4b'（送る範囲）＋ 5（TCPDF をコマンドと画面）＋ 6（clone を 3200 に立てて審査員の環境） | 約6分・Claude 6回ほど | 区切り・push の前。**裏で流し、その間に次の作業を進める** |

- 結果は表で出る（`runs/check/check-all-*.md` にも残る）。❌ の行だけ中身を読み、直して `fix:` でコミット、もう一度流す
- dev（3000）は触らないが work/ と runs/ は同じ。`check:all` の間は dev の画面のボタンを押さない（押すと、その実行の php のサーバを 2d が「残っている」と数えて ❌ になる）
- `targets/` に自分の題材があると、題材のカードは 5 枚以上になる（4a は同梱の4つがそろっているかを見る）
- 6 の clone は**コミット済み**の内容。コミット前の変更は入らない
- スクリプトに無いのは 4g（判定の件数の守り。変えたときだけ手で）だけ
- 期待値を変えたら `scripts/check/expected.ts` と下の表の両方を直す

以下は各項目の中身（スクリプトが何を確かめているか、手で確かめ直すときの手順）。

## 1. 機械の確認

```sh
npm test && npx tsc --noEmit && npm run lint
```

期待: 全部通る（件数は前回の報告から減っていない）。

## 2. サンプル（Claude なし）

```sh
npm run samples
```

期待: A 無害（機械）／B・C 残った差 3 行・判定なし／D 壊れている（機械・新で出力なし）。

### 2b. ほかの題材（Claude なし）

```sh
npm run samples -- --subject worklog
```

期待: Python 3.10 → 3.12 の作業日報。A 無害（機械）／B 残った差 2 か所（3 行）／C 残った差 3 か所（3 行）。
```sh
npm run samples -- --subject bookshop
```

期待: Web 型（架空書店・PHP 7.4 → 8.5 の内蔵サーバ・32 件。export だけ CSV・Shift_JIS のテキスト）。無害（機械）23／order-27 だけ壊れている（機械・HTTP 500）／残る 8 件（list・export・order-4・8・12・19・21・25）は判定なし。
終わったあとに `ps aux | grep "[p]hp -d display_errors=0 -S"` が 0 件（サーバが止まっている）。
Claude ありなら（8 回）: 8・21 壊れている／4・12・19・25 無害／list は無害か要確認（並び順だけ）／export は無害か要確認（割引率の表記「10.0」→「10」だけ）。

ファイル型（run.type "files"）を変えたときは、worklog の runs/ の出力で targets/ に一時的な題材を作って流す（片方に無いファイルが「出力なし」になる）。⚠️ 終わったら targets/ を消す。

## 3. サンプル（Claude あり。⚠️ API を2回呼ぶ）

```sh
npm run samples -- --judge
```

期待: A 無害（機械）／B 要確認／C 壊れている（残った明細の和と合計が合わない計算つき）／D 壊れている（機械）。
最新の `runs/*/report.json` で、各 finding の `machineNotes` が無いこと（あれば、Claude の根拠を機械が崩したということ。中身を読んで報告する）。

## 4. 画面（dev を起動し直してから。Claude in Chrome で確かめてよい）

dev は**起動し直す**（メモリに前の実行が残っていると、同梱の結果が出ない）。開いた直後は初回のコンパイルで数秒何も出ない。
コンソールに残っている古いエラーに惑わされないよう、消してから読み込み直す。

## 4b. 送る範囲（C）

設定の `claude.send` を一時的に output → none に変えて `GET /api/runs` を見る（dev は起動し直さなくてよい）。
output: 原因探しが理由つきで押せない（API も 400）。none: 判定し直しも押せない・`npm run samples -- --judge` が止まる・実行はキー無しで通る。
`claude` の行を消すと設定の読み込みで止まる。⚠️ 終わったら `git checkout` で戻す。

## 6. 審査員の環境（clone・計画の区切りと提出前）

```sh
git clone <このリポジトリ> <scratchpad>/clone && cd <scratchpad>/clone && npm ci && npm run dev
```

⚠️ いま動かしている dev を止めてから（ポートが同じ）。clone には vendor/・.env・runs/・work/ が無い＝審査員と同じ。
期待: 題材が4つ選べる／見積書・作業日報・架空書店は同梱の結果（原因・送った全文・「同梱の『当てて確かめた結果』を見る」→ 直りました）／
見積書の実行は「実行に要るものがありません …lib-old/vendor」（run.needs）と次の一手で止まる／TCPDF は composer の案内で止まる。
あわせて `npx next build` が通ること（警告「Dynamic filesystem access」5件は、ローカルで動かすツールなので無害）。
